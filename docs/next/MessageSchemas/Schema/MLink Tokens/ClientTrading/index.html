ClientTrading

#Message NameDescription
2358AtsDegrossAuctionSchedulePublished by the degrossing execution engine at start of day; each row's state updates as the

sequence runs. Clients consume this — the sequence is never hard-coded client-side.

Sequence: Trial 9:55 CST, then Real auctions 10:00 / 10:05 / 10:10 / 10:15 CST, 3 expiries each.
2357AtsDegrossAvailabilityPublished by the degrossing execution engine once a minute from open + 5 minutes until the final

auction of the day, smeared to a fixed publish rate. Every candidate ticker is published with a

status: Available, Suspended, DayClosed, or the reason it is not offered — so a client can always

see why a position is not degrossable.

Strike is a TICKER-level fact shared by all three expiries, chosen from flex instruments that

actually exist (nearest the underlier), and frozen at the ticker's first publish of the day.

The per-expiry block (3 entries) carries the SR-controlled economics; block index = expiry slot =

SpdrParentOrder groupingCode (1/2/3). Auction sequence state lives on AtsDegrossAuctionSchedule

(2358). Publish-only: no archive directives and .Archive() is never called — published messages

are captured automatically.

A ticker is only published when it has a current-day stock book quote or print; names with no

today market are not advertised at all.

Retired field numbers (NEVER reuse): 112 (per-slot strike; strike is row-level at 103),

101 (row-level srRate; the rate is per expiry at 120).

Replaces AtsDegrossRevConSpreads (2355).
2359AtsDegrossFlexRequestPublished by the degrossing execution engine after the close, one record per instrument we want

to exist for the next trading day and do not already see as a FlexOptionDefinition (4435).

Keyed by the OptionKey we want, so requested-versus-existing is a straight key comparison.

The request set is "desired strike x 3 auction expiries x call and put, minus what already

exists", which covers both triggers without special cases: a strike that drifted past the

selection band yields six requests at a new strike, and a calendar roll yields two at the

existing strike for the newly appeared expiry.
2360AtsDegrossMarketSummaryPublished by the degrossing execution engine at each auction close. This is the PUBLIC

post-auction disclosure — venue totals only, never per-client figures (per-order results are

AtsDegrossRevConResult (2356)). The WTS merges these onto LiveGridDegrossMarket (6973) rows.

Prices are PACKAGE space, like 2356/4030 — the book matches there; consumers rebase +strike for

trader R/C display. Publish-only: no archive directives and .Archive() is never called.
5240AtsDegrossRevConGatewayRecords inserted, updated, or replaced into this table are validated by the SRSE gateway and

converted to SpdrParentOrder (4095) records via ToSpdrParentOrder (parentOrderHandling=DegrossAuction,

orderLimitType=RcPrem). The 4095 is the only EE order ingress; this table is never consumed by the EE.

Each record is one order line: a single ticker/expiry RevCon package (1 call + 1 put + 100 shares per unit).

Strike and expiry are SR-controlled: resolved from the AtsDegrossAvailability (2357) expiry slot

addressed by groupingCode; never a client input.
2356AtsDegrossRevConResultPublished by the degrossing execution engine: Received on order arrival, then per-auction

results after each event in the day's sequence (Trial 9:55 CST, Real 10:00/10:05/10:10/10:15;

see AtsDegrossAuctionSchedule (2358)), Final after the order's last event. The WTS merges

per-(ticker, expiry) results into LiveGridBasketDegrossDetail (6912) rows; per-auction rollups

drive the Basket Manager summary boxes.
2355AtsDegrossRevConSpreadsDeleted once the EE publisher and WTS join cut over; do not add consumers. The number is

reusable a few weeks after deletion.
5290AutoHedgeSymbolAutoHedgeSymbol records are published by autohedge servers and contain all valid hedge target symbols. Execution engines reject auto-hedge requests for hedgeSecKeys that are not in this set.
2495AutoResponderVegaDir
7941CntrlVenuePolicyportfolio control: which venues a slot quotes and the per-venue turn threshold

Authored in the control UI per account and scope; saveId generations like the other Cntrl* records.

The generator resolves the most specific enabled row for a ticker (Ticker > RiskLetter > Accnt)

and stamps its rows onto the {Venue} repeater of every EdgeParentBucket (7934) it emits. The

mandates themselves are identical per venue; behaviour differences (fee profile, randomization)

live in the model probabilities and the core's venue config, never in the mandate.
7940EdgeBucketRiskStategateway-published per-slot cross-venue risk aggregation - the generator's refill input

Same pkey as EdgeParentBucket (7934). Risk is the slot's position across every venue mandate in

the metric units of the 7934 bounds (fixed 1e2 dollars); room is bound minus risk. Everything is

stated as of checkpointFillNumber, the last EdgeExecution (9505) the gateway folded, so the

generator and the gateway agree on what a later fill means. The generator widens a slot only after

a 7940 stamped with the slot's own last slotVersion (the refill handshake). Cadence: material

change plus a slow periodic republish (the 7931 pattern).
7932EdgeGeneratorHeartbeatOwner-level liveness: one heartbeat per (accnt, strategyCode) - NOT per-slot endDttm refresh.

The gateway pulls ALL of an owner's slots on 2-3 missed beats (EdgeParentQuoteAck (7931) status Pulled,

reason OwnerLost). Proves the process is alive, not that its decisions are fresh - pins/staleness own that half.
7933EdgeGeneratorRiskStateControl-lattice cell state, published DIRECTLY by the generator (.Publish, no MLink hop) on each

pass: current risk vs zero point, normalized balance, and the composed per-side controls - the

visualization/audit surface for the SPARC portfolio tool (skew x term heatmaps) and the CH trail.

Publish cadence: covered cells only (open candidates or held positions), material change plus a

slow periodic republish - the 7931 ack pattern; LVC replace gives tools current state on subscribe.

Bucket vocabularies are PLACEHOLDERS pending ruling; they are shared enums (this def is their

defining site) used as viewKey names by the CntrlBalanceCurve (7937) lattice surfaces.
7945EdgeParentBracket
7946EdgeParentBracketAck
7934EdgeParentBucketgenerator-to-gateway: a two-sided standing quote mandate for a BUCKET of series

One slot = one control-lattice cell (ticker x callPut x skewBucket) rendered onto one concrete

expiry. The generator owns the strike band: the cell's members at emission, re-issued as the

underlier moves the band; a blur member goes to the heavier of its two skew buckets so two slots

on one expiry never present intersecting bands to the core's ownership rule.

The gateway gates each side and mints EdgeBucketMandate (9507) per side per listed venue; the

venue mandates are IDENTICAL (sizes are per venue). It never derives intent the generator did not

state. Cross-venue risk bounds (minRisk/maxRisk) are ABSOLUTE and generator-authored; the gateway

turns them into per-venue room grants (9507 / EdgeBucketRoom 9512) and publishes the aggregate on

EdgeBucketRiskState (7940). slotNumber / slotVersion / restart-epoch rules as EdgeParentQuote (7930).

The instrument-shaped path (7930 -> EdgeOrder 9502 -> order engine) is a separate product.
7939EdgeParentBucketAckgateway-to-generator: slot status and consumption for an EdgeParentBucket (7934)

Same pkey as 7934. Status is the worst across the slot's live venue mandates

(Rejected > Pulled > Held > Live > Accepted); sizes are sums across venues per side; fills fold per

incarnation from EdgeExecution (9505) carrying bucketNumber in parentNumber. Effective sizes are

what stands after the gateway's own room narrowing; requested sizes echo the slot, so the generator

never re-widens blindly into a narrowed venue.
7930EdgeParentQuoteStanding two-sided quote mandate, per instrument: a superset of EdgeOrder (7860) minus the venue binding.

The pkey is the slot identity - a new record wholly replaces the previous one (LVC native); no action enum,

no cancel/replace chains: pull = enabled:No (or both sizes 0). The EdgeMandateGateway risk-checks and fans out

instrument -> exchange: engine mass-quote path on MQ-capable routes, per-side EdgeOrder (7860) tied mandates otherwise.

Take blocks grant conditional, separately-budgeted take rights - never implied by quote semantics.
7931EdgeParentQuoteAckGateway state per quote slot: accept/reject + live fan-out + per-side consumption. Same slot pkey as

EdgeParentQuote (7930) - LVC replace semantics; consumption meters span replaces WITHIN a slot

incarnation (slotNumber) - a replace re-aims intent, a new incarnation starts fresh.

Published on state change + heartbeat.

4025SpdrMLegBrkrEventPublished when a new (or cancel/replace) parent order arrives causing a broker to begin working, and again when the parent order terminates and the underlying broker stops working. The initial version contains state and market data from just after the initial risk check and first attempt at generating child orders.
4030SpdrMLegBrkrStateSpdrMLegBrkrState records are published by execution engines and describe the current state of a broker that is managing a SpiderRock multi-leg parent order. These records include a description of the active child orders (stock leg and up to six option legs) managed by the broker. Records are updated whenever a child order changes and also at other times, but are not completely live and may not always reflect current market data or limit levels for working orders.

4070SpdrParentBrkrStateParent broker state record (unified).

Published by SpiderRock Execution Engines. Describes the current state of one (or more) parent orders including active child orders, market data snapshot, and progress statistics. If a parent order is cancel/replaced, the entire chain is represented by a single broker state record.
4075SpdrParentBrokerSummaryCreated at the end of a trading period. Summarizes activity across Stk/Fut/Opt/MLeg broker state records for an accnt + secType + tickerSrc + spdrSource + parentOrderHandling + tradingPeriod + clientFirm combination.
4080SpdrParentCancelRecords inserted into this table cancel the parent order identified by parentNumber + accnt + clientFirm, if active and cancellable.
4085SpdrParentExecutionPublished by execution engines upon child order fills. Aggregates fill details, cumulative statistics, and risk/pricing state at time of execution. Updates again at F+1m and F+10m as post-execution mark data becomes available.
4086SpdrParentExecutionV2Published by execution engines upon child order fills. Aggregates fill details, cumulative statistics, and risk/pricing state at time of execution. Updates again at F+1m and F+10m as post-execution mark data becomes available. V2 adds contingent cancel, counterparty, and extended markup detail.

SpdrParentExecution records are published every time a parent order execution is received. They also update as additional post execution mark information is available at F+1m and F+10m.
4090SpdrParentLimitClient-supplied (via SRSE) limit parameters for parent orders with orderLimitType=Aux. Can be updated before or after a parent order begins working; updates do not constitute cancel/replace operations and will influence the limit(s) used when working child orders.
4095SpdrParentOrderParent orders received via FIX, SRSE, SpiderRock GUI tools, or third-party vendor systems are all visible in this table immediately after receipt.

Parent orders can be for stocks, futures, options, or spreads, and can be one-sided (agency) or two-sided (facilitation). Records are immutable (no updates) and are published to the SpiderRock elastic cluster on arrival.
4100SpdrParentReportTracks the current state of a parent order across its lifecycle. Updated as order state changes; published to the SpiderRock elastic cluster upon reaching a terminal state (closed, rejected, filled, etc.).
4195SpdrParentReviewRequestSpdrParentReviewRequest records created when a parent order is submitted with StageType=StageReview. These records indicate that an external review of the parent order has been requested.
4200SpdrParentReviewResponseSpdrParentReviewResponse records are created when a parent order review request is completed

AWS S3 / Parquet

All SpiderRock historical data is available as Parquet files hosted on AWS S3. This page covers how the files are organized, how to download them, and how to read them with common tools.

Bucket Layout​

Files are stored in the srhistdatastore bucket and organized by release stage, region, and dataset:

s3://srhistdatastore/<stage>/<REGION>/<Dataset>/[type=<EQT|FUT>/][ts=<exchange>/]date_p=<YYYY-MM-DD>/<Dataset>_<YYYY-MM-DD>.parquet
LevelValuesNotes
<stage>v8, v8_latestSee Release Stages.
<REGION>US, EU
<Dataset>e.g. OptionIntradayHistMatches the name in the Data Dictionary.
type=EQT, FUTOptions and surface datasets only: equity options vs. options on futures.
ts=e.g. NMS, CMEExchange / ticker source, on datasets partitioned by exchange. EU data is partitioned by exchange.
date_p=YYYY-MM-DDPartition date. For datasets that capture only market hours or end-of-day data, date_p usually corresponds to the trading date.

Not every dataset uses every level — check the dataset's folder in the AWS console, or the example path in its data dictionary entry.

Partitioning and Timestamps​

  • Files are partitioned Hive-style by date. The partition is named date_p to avoid conflicts with date columns inside the files.
  • date_p follows Central Time for US datasets and Central European Time for EU datasets.
  • All timestamps inside the files are in UTC.
  • Data is sorted by ticker, option characteristics, and timestamp where applicable. Filtering on partition keys (date_p, type, ts) in your WHERE clause gives the best read performance.

Full History Files​

A small number of datasets are published as a single Full History file that is rebuilt every day, instead of one file per trading date: StockCloseMarkHist_AllHist, TickerHistory3_AllHist, and ReturnFactorsHist_AllHist. Full History files are published to v8 only. Download the newest file each day to get the complete, current history. See Release Process for how these files are updated.

Downloading the Data​

During onboarding, you receive either AWS credentials (CLI and web portal) or a cross-account IAM role. SpiderRock recommends logging in to the AWS portal first to explore the folder structure and confirm which datasets you are subscribed to.

AWS CLI​

Once you have identified the data you need, use aws s3 sync to download it:

export AWS_ACCESS_KEY_ID=<your access key id>
export AWS_SECRET_ACCESS_KEY=<your access key secret>

aws s3 sync s3://srhistdatastore/v8/<REGION>/<Dataset>/... <your local copy path>

IAM Role (AWS CLI)​

If you access SpiderRock data through a cross-account IAM role, add a named profile to your ~/.aws/config file. The AWS CLI assumes the role automatically when the profile is used.

~/.aws/config
[profile spiderrock]
role_arn = <SPIDERROCK_ROLE_ARN>
source_profile = default
role_session_name = historical-data-download

Pass the profile to aws s3 sync with the --profile flag:

aws s3 sync \
    s3://srhistdatastore/v8/US/SurfaceFixedGridIntradayHist/type=EQT/date_p=2026-02-09/ \
    ./SurfaceFixedGridIntradayHist/date_p=2026-02-09/ \
    --profile spiderrock

IAM Role (Python)​

Use the AWS Security Token Service (STS) to assume the SpiderRock role and obtain temporary credentials before downloading.

import boto3

# Create an STS client using credentials from your own AWS account.
# The IAM user or role running this code must be permissioned to assume the SpiderRock-provided role.
sts = boto3.client("sts")

# Replace with the role ARN provided by SpiderRock.
provided_role = "<SPIDERROCK_ROLE_ARN>"

response = sts.assume_role(
    RoleArn=provided_role,
    RoleSessionName="historical-data-download",
)

s3 = boto3.client(
    "s3",
    aws_access_key_id=response["Credentials"]["AccessKeyId"],
    aws_secret_access_key=response["Credentials"]["SecretAccessKey"],
    aws_session_token=response["Credentials"]["SessionToken"],
)

# In production, parameterize the Key and run on a schedule after the dataset's delivery time.
s3.download_file(
    Bucket="srhistdatastore",
    Key="v8/US/SurfaceFixedGridIntradayHist/type=EQT/date_p=2026-02-09/SurfaceFixedGridIntradayHist_2026-02-09.parquet",
    Filename="SurfaceFixedGridIntradayHist_2026-02-09.parquet",
)
Scheduling downloads

Schedule each download after the dataset's delivery time in Data Availability. For two-stage datasets, the file at a given path is replaced when the final version is published — schedule your pickup after the final delivery time if you want a single, complete file.

Reading the Data​

Many tools support Parquet. Internally, SpiderRock uses DuckDB and Polars. The examples below read one day of SpiderRock volatilities for AAPL from OptionIntradayHist.

DuckDB​

SELECT
    okey_tk,
    okey_dt,
    okey_xx,
    okey_cp,
    date,
    srvol
FROM
    read_parquet('./OptionIntradayHist/**', hive_partitioning = true)
WHERE
    date_p = '2025-12-26'
    AND okey_tk = 'AAPL'

Polars​

import polars as pl
import datetime

df = (
    pl.scan_parquet("./OptionIntradayHist/**")
    .filter(
        (pl.col("date_p") == datetime.date(2025, 12, 26)) & (pl.col("okey_tk") == "AAPL")
    )
    .select(["okey_tk", "okey_dt", "okey_xx", "okey_cp", "date", "srvol"])
    .collect()
)

Working with Complex Data Types​

Some datasets use nested Parquet types. For example, the OrderLegs column in AuctionNotice is a list of struct. To flatten it into one row per leg with each struct field as its own column:

df = (
    pl.read_parquet("./AuctionNotice/date_p=2025-11-03/AuctionNotice_2025-11-03.parquet")
    .explode("OrderLegs")
    .unnest("OrderLegs", separator="_")
)

Each dataset's nested columns are documented under Complex Fields in its Data Dictionary entry.

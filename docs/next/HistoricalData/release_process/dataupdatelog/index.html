DataUpdateLog

The DataUpdateLog is the record of every fix, schema change, and backfill made to SpiderRock V8 historical data. Each entry tells you which dataset and dates were affected, which fields changed, why, and when the update reached v8_latest and v8.

It is delivered like any other dataset, so you can query it directly or join it to your own ingestion logs to automate re-syncs.

What the DataUpdateLog does not cover

The DataUpdateLog records improvements to historical data that has already been delivered. It does not record:

  • Data delays, or the later delivery of data that was delayed. These are communicated by email — see Data Delays.
  • Fixes to a file that was incomplete or incorrect at delivery. These are pushed directly to both v8 and v8_latest and handled under Data Delays.
  • The preliminary-to-final replacement for two-stage datasets, which is part of the normal daily delivery.

Location​

MethodLocation
AWS S3s3://srhistdatastore/v8_updatelog/v8_updatelog.parquet
SnowflakeHIST_DATA_PROD.V8_US.V8_UPDATELOG

The log covers both US and EU datasets; filter on region.

The DataUpdateLog is not produced daily. It is only updated when an entry is added or changed, so the file's last-modified time tells you when there is something new to review. See Checking for Updates.

Schema Definition​

Field NameData TypeDescription
updateNumberintUnique, sequential identifier for the entry. Higher numbers are more recent.
regionstringUS, EU, or ALL.
datasetstringDataset affected, as named in the Data Dictionary.
typestringInstrument type: EQT (equities / equity options) or FUT (futures / options on futures).
tsstringComma-separated list of exchanges (ticker sources) affected, e.g. NMS or CME,COMEX,NYMEX,CFE,CBOT.
tradingDateJSONTrading dates affected. See Reading tradingDate.
updateReasonstringCategory of update. See Update Reasons.
descriptionstringPlain-language summary of what was wrong or what changed.
impactedFieldsJSONArray of affected column names, e.g. ["prtVolume"]. ["all"] means entire rows were affected.
v8LatestEffDatedateDate the update was released to v8_latest.
v8EffDatedateDate the update was (or will be) promoted to v8. A date in the future means the update is still in its 30-day adoption window.
impFwdDatastringYes if the update also changes how data is produced for new trading days; No if it is a one-time historical fix.

Update Reasons​

updateReasonMeaning
dataCorrectionIncorrect values were fixed, or rows were removed or corrected.
recalcValues were recomputed (e.g. surfaces or analytics recalculated).
FieldUpdateThe values of specific fields were updated.
SchemaUpdateColumns were added, removed, renamed, or changed type.
HistoricalBackfillMissing history, rows, or fields were added.

Reading tradingDate​

tradingDate is a JSON object in one of three forms:

{"type": "single", "date": "2026-03-09"}
{"type": "list",   "dates": ["2026-03-09", "2026-03-10", "2026-03-16"]}
{"type": "range",  "start": "2024-01-02", "end": "2026-06-30"}

Example Queries​

Every update to a dataset you use, newest first (DuckDB):

SELECT updateNumber, dataset, region, type, updateReason, description,
       tradingDate, impactedFields, v8LatestEffDate, v8EffDate
FROM read_parquet('v8_updatelog.parquet')
WHERE dataset = 'OptionPrintSetHist'
ORDER BY updateNumber DESC;

Updates that will reach v8 in the future — what's coming to v8 (Snowflake):

SELECT dataset, region, type, description, v8LatestEffDate, v8EffDate
FROM HIST_DATA_PROD.V8_US.V8_UPDATELOG
WHERE v8EffDate > CURRENT_DATE()
ORDER BY v8EffDate;

Updates promoted to v8 since your last sync — the dates you need to re-download:

SELECT dataset, region, type, tradingDate
FROM HIST_DATA_PROD.V8_US.V8_UPDATELOG
WHERE v8EffDate > '<your last sync date>'
  AND v8EffDate <= CURRENT_DATE();

Checking for Updates​

Because the DataUpdateLog only changes when there is a new or updated entry, you don't need to download it every day. Instead, check whether it has changed, and download and review it only when it has.

1. Check whether the file has changed​

AWS CLI – compare the file's LastModified and ETag with the values from your last check:

aws s3api head-object \
    --bucket srhistdatastore \
    --key v8_updatelog/v8_updatelog.parquet \
    --query '{LastModified: LastModified, ETag: ETag}'

Python – check, and download only if the file has changed:

import json
import pathlib
import boto3

BUCKET = "srhistdatastore"
KEY = "v8_updatelog/v8_updatelog.parquet"
STATE = pathlib.Path("updatelog_state.json")   # remembers the last version you reviewed

s3 = boto3.client("s3")  # or the STS-based client from the AWS S3 / Parquet page
etag = s3.head_object(Bucket=BUCKET, Key=KEY)["ETag"]

last_etag = json.loads(STATE.read_text())["etag"] if STATE.exists() else None
if etag != last_etag:
    s3.download_file(BUCKET, KEY, "v8_updatelog.parquet")
    STATE.write_text(json.dumps({"etag": etag}))
    print("DataUpdateLog changed - review new entries")
else:
    print("No changes")

Snowflake – check whether there are entries newer than the last one you reviewed:

SELECT MAX(updateNumber) AS latest_update
FROM HIST_DATA_PROD.V8_US.V8_UPDATELOG;

If latest_update is higher than the last updateNumber you reviewed, there are new entries.

You can run this check on whatever schedule suits you — for example, once a day after your normal download.

2. Review the new entries​

When the file has changed, filter it to the entries you haven't seen yet (updateNumber greater than the last one you reviewed) and to the datasets, regions, and types you consume.

3. Re-download the affected dates​

For each relevant entry, re-download the dates in tradingDate from the location you use:

  • v8_latest – once v8LatestEffDate has passed.
  • v8 – once v8EffDate has passed.
note

An entry is added to the log when the update is released to v8_latest, which is usually 30 days before it reaches v8. The log does not change again on the v8 promotion date. If you consume v8, keep track of entries whose v8EffDate is still in the future, and re-download those dates once the date passes — the Updates promoted to v8 since your last sync query above returns them.

Example Entry​

FieldValue
updateNumber1125
regionUS
datasetOptionIntradayHist
typeEQT
tsNMS
tradingDate{"end": "2021-10-07", "type": "range", "start": "2020-08-07"}
updateReasondataCorrection
descriptionExpired options remained in OptionIntradayHist on 213 trading dates between August 7, 2020 and October 7, 2021. We removed these expired records, about 45.8 million rows in total.
impactedFields["all"]
v8LatestEffDate2026-11-04
v8EffDate2026-12-05
impFwdDataNo

This entry tells you that, for US equity options in OptionIntradayHist, expired-option rows were removed on trading dates within the range August 7, 2020 to October 7, 2021 (the exact count is in description). The correction is available in v8_latest from November 4, 2026 and will be promoted to v8 on December 5, 2026. Because impFwdData is No, it does not change how new trading days are produced.

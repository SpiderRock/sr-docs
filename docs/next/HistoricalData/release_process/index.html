Release Process

This section explains how SpiderRock publishes historical data and how changes to it reach you. It answers three questions:

  1. When does each day's data arrive? – See Data Availability and Two-Stage Release.
  2. What happens when published data is fixed or a schema changes? – See Fixes, Changes, and Enhancements.
  3. How do I find out about changes and delays? – See DataUpdateLog and Data Delays.

Three Kinds of Release​

 Daily data                Two-stage intraday data            Fixes / changes / enhancements
 ──────────                ───────────────────────            ──────────────────────────────
 Trading day closes        20:00 CT T+0  preliminary file      Released to v8_latest
        │                         │                                   │
        ▼                         ▼                                   │  30-day adoption window
 Published to v8 and       04:00 CT T+1  final file                   ▼
 v8_latest on schedule     replaces it at the same path        Promoted to v8 (weekly run)
                           (v8 and v8_latest)
  1. Daily data – Each trading day's file is published once, to both v8 and v8_latest, at the time listed in Data Availability.
  2. Two-stage intraday data – A small set of US intraday datasets publish a preliminary file the evening of the trading day and a final file the next morning. See Two-Stage Release.
  3. Fixes, changes, and enhancements – Changes to data that has already been published go to v8_latest first and are promoted to v8 after 30 days. If an update also changes data going forward (for example, columns added or removed), new trading days are updated in both locations on the same day, with advance notice. See Fixes, Changes, and Enhancements.

Choosing Between v8 and v8_latest​

Both locations contain stable, production-quality data and are delivered on the same daily schedule. The only difference is when updates to history arrive. v8_latest is the leading edge: fixes and new fields arrive as soon as they are released. v8 receives the same updates after a 30-day adoption window, on a scheduled weekly promotion.

The adoption window gives you time to review an update — and test it against v8_latest — before it reaches v8. You decide when to take it: switch to v8_latest early, or let it arrive in v8 on its promotion date.

When a Fix Reaches v8​

A fix is released to v8_latest first and promoted to v8 in the first weekly promotion run after 30 days. The exact dates for every fix are recorded in the DataUpdateLog as v8LatestEffDate and v8EffDate.

Two-Stage Final Files​

The final file for a two-stage dataset is part of the normal daily delivery, not a correction. It is published to both v8 and v8_latest the next morning, does not wait 30 days, and is not recorded in the DataUpdateLog.

How You're Notified of Changes​

Every change to historical data is recorded in the DataUpdateLog, which you can query like any other dataset.

SpiderRock also sends an email notification for large or impactful releases. Smaller releases — for example, a single-day improvement that doesn't affect calculations or schemas — may not trigger a notification, but are always recorded in the DataUpdateLog. For delivery delays, see Data Delays.

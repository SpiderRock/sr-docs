SRSE vs. MLink

SRSE and MLink give clients the same SpiderRock Connect live data through two different interfaces. SRSE is a MariaDB database: you read current data with SQL SELECT and upload orders, positions and models with INSERT or REPLACE. MLink is a web API: you pull snapshots over HTTP/REST or stream live updates over WebSocket, in JSON or Protobuf.

Rule of thumb: choose SRSE for bulk, SQL-driven work from inside a SpiderRock network connection. Choose MLink for internet access, live streaming and on-demand option calculations. Both can enter parent orders, so one firm can use each where it fits.

Why SRSE​

  • Whole universe in one query. One SELECT returns every current record that matches, and SQL filters, sorts and joins run on the server.
  • Uploads become live data. Rows inserted into SRSE tables are published as live records that the rest of the platform consumes: orders, positions, locates, restricted lists and theoretical models.
  • High-throughput order gateway. Parent order baskets load in bulk, usually with LOAD DATA INFILE, and work with SpiderRock execution algos and GUI tools.
  • Prior-day and historical tables. Prior-day surfaces and greeks, archived positions and marks, and historical underlying volatility sit beside live data.
  • No SDK to learn. Any SQL client or MariaDB driver works, and the docTables and docColumns tables describe every table and column.
  • Private instances. A dedicated SRSE server pool is available on its own port.

Why MLink​

  • Connect from anywhere. Market data endpoints are reachable over the public internet on port 443, so you need no VPN or cross-connect to start.
  • Live streaming. WebSocket pushes each update as it happens. MLinkStream follows a filter or the full universe; MLinkSubscribe follows a list of keys you add to or remove from on the fly.
  • Fast, compact encoding. Protobuf shrinks payloads, and clients saw about 10x lower end-to-end latency than JSON in demanding streams.
  • Live calculators. Price options and get greeks on demand for listed and FLEX options, singly, as spreads or in baskets, overriding volatility, underlying price or rates.
  • Efficient symbol scoping. Ticker baskets and stripes cover large symbol sets. In one test, a basket filtered about 166,000 messages in 2.12 s versus 8.68 s for a WHERE clause.
  • Self-service keys and test data. Create API keys yourself from the SpiderRock Connect home page, and build against delayed or simulated data.
  • ATS auctions. Initiate and respond to SpiderRock Connect ATS auctions.
